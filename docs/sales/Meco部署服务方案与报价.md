## 1. 项目概述

客户需要把 Meco 真正用起来，而不是装上一个软件。本次服务覆盖四件事：**替客户部署好、能出立案资料、能发邮件、把员工教会**，并在上线后一个月内陪跑解决问题。

### 1.1 客户需求与实现方式

| 客户需求 | 实现方式 |
|---|---|
| 替我们部署起来、使用起来 | 安装部署、AI 网关接入、账号与初始化配置，员工登录即用 |
| 能出立案资料 | 内置 Office 技能直接生成 Word / PDF；配套模板库、提示词与知识库，并配置专职文书数字人 |
| 可以发送邮件 | 消息通道接入企业邮箱；配置专职邮件数字人，负责邮件读取、撰写、发送、回复与转发 |
| 培训如何使用 | 提供课件、学员手册与练习卡，开展现场培训 |
| 使用过程中有问题可以咨询 | 上线后一个月内提供远程支持与问题闭环 |
| 前期方案咨询 | 实施前的需求梳理、场景设计与可行性确认 |

### 1.2 服务边界

**本次服务包含**：部署配置、场景搭建、模板与知识库建设、培训、一个月使用支持。

**本次服务不包含**：

- AI 模型调用费用——由客户自行向模型服务商采购，与服务费无关；
- 客户邮箱账号的申请、开通与授权；
- 立案资料内容的代写、审核与法律责任；
- 硬件与网络环境的准备；
- 超过一个月的持续支持（可另签年度维保，见 4.5）。

### 2.2 立案资料能力

| 项 | 内容 |
|---|---|
| 文书数字人 | 配置专职数字人，负责立案资料的生成、修订与格式整理 |
| 模板库 | 按客户实际文书类型配置生成模板与提示词，确保格式、要素、用语符合客户要求 |
| 知识库 | 将客户提供的法规、内部规范、历史文书等资料入库，生成时带出处引用 |
| 产出格式 | Word / PDF，可直接归档或再编辑 |

> 交付物为**模板、提示词、知识库与使用方法**，教会客户员工自行生成。我们不代写具体文书，也不对文书内容的法律准确性承担责任。

### 2.3 邮件能力与邮箱哨兵

| 项 | 内容 |
|---|---|
| 邮箱接入 | 设置 → 消息通道 → 邮箱，配置 SMTP / IMAP，完成发送测试 |
| 邮件数字人 | 配置专职数字人，支持读取、检索、撰写、发送、回复、转发、整理邮件 |
| 邮箱哨兵 | 配置定时数字人，自动巡查邮箱并完成"发现 → 下载 → 处理 → 通知"全流程 |
| 场景配置 | 如"收到某类邮件后自动草拟回复""生成文书后发送给指定收件人"等常用场景 |

**邮箱哨兵工作流程**：

```
定时触发
   │
   ▼
巡查邮箱（email_list / email_search）
   │
   ▼
识别含资料的邮件 ──否──► 跳过
   │是
   ▼
下载附件（email_attachment_download）
   │
   ▼
处理：入知识库 / 生成文书 / 整理归档
   │
   ▼
通知负责人（企业微信 / 飞书 / 钉钉 / 邮件 / 桌面提醒）
```

巡查周期、识别规则、处理动作、通知对象均在实施阶段与客户确认后配置。

**邮件能力的技术边界（需客户提前知悉）**：

1. 一套安装对应一个邮箱身份，邮件统一从配置的账号发出，`From` 地址固定为该账号，不支持自定义显示名或别名地址；
2. 邮件工具仅在数字人自己的对话与定时运行中可用，普通对话窗口无法调用，因此邮件能力必须以数字人形式交付；
3. 仅支持账号密码（应用专用密码）鉴权，不支持 OAuth；IMAP 固定使用 993 端口 SSL，与 SMTP 共用同一套账号密码；
4. 需要客户邮箱已开启 SMTP / IMAP 服务，并提供应用专用密码。

### 2.5 法院立案自动上传（协助实施）

**实现方式**：通过 AI 操作内置浏览器完成。AI 驱动真实浏览器导航至法院诉讼服务平台，按人工同等步骤完成登录、案件选择、立案资料上传与提交；全过程可视，使用方可随时接管或中止。重复性操作封装为可复用的 `.js` 脚本，AI 只负责判断做什么、何时做，脚本负责精确执行，避免每次重新推理。

**双方职责划分**：

| 我方（协助实施） | 使用方 |
|---|---|
| 梳理立案上传流程，划分可自动化与需人工判断的环节 | 提供法院平台账号与授权，确保账号具备相应权限 |
| 编写浏览器操作脚本，完成端到端联调测试 | 确认立案业务流程与资料规范 |
| 将法院平台域名加入 AI 浏览器允许列表 | 日常使用中的监控、人工复核与最终提交确认 |
| 培训使用方人员启动、监控与异常处理 | 平台侧账号异常时的处理 |

**不承诺事项**：

| 项 | 说明 |
|---|---|
| 平台改版适配 | 法院平台界面变更后需重新联调，按人日 ¥1,600 另计 |
| 反自动化策略 | 不绕过平台方的验证码、风控与频率限制 |
| 合规判断 | 使用自动化方式提交是否符合平台规定及所在司法辖区要求，由使用方自行判断，我方不作合规结论 |
| 立案结果 | 不承诺立案材料的审核结果与法律效力 |

**技术前提**：企业版需将法院平台域名加入 `browserPolicy.allowlist`，否则 AI 浏览器无法访问该站点。

## 6. 选配方案 · NAS 集中部署

### 6.1 可行性结论

**可行。** 产品提供无头服务端构建（linux-x64），官方配套 Docker 镜像与编排文件，专为 7×24 常驻运行设计。资料集中存放于 NAS、由系统定期自动产出总结报告，属于该形态的标准用法。

### 6.2 部署形态

```
┌──────────────────────────────────────────┐
│  NAS（x86_64，支持 Docker）                │
│                                          │
│  ┌────────────────┐   ┌────────────────┐ │
│  │ halo-server    │   │ NAS 存储池      │ │
│  │ 容器 :8080     │◄──│ /volume1/资料  │ │
│  └───────┬────────┘   └────────────────┘ │
│          │ 数据目录挂载到存储池             │
│          ▼                               │
│  ┌────────────────────────────────────┐  │
│  │ 知识库（监视 NAS 文件夹）            │  │
│  │ 定时数字人（按月汇总）→ Word/PDF    │  │
│  └────────────────────────────────────┘  │
└──────────────────────────────────────────┘
         │ 浏览器 / 桌面端 / 手机访问
         ▼
      员工
```

- 服务端以 Docker 容器运行，数据目录挂载到 NAS 存储池，资料与产出全部落在 NAS 上；
- 员工通过浏览器直接访问，或用桌面端、手机端远程接入；
- 镜像在构建机构建并导出，NAS 上导入即可运行，**运行阶段可完全离线**。

### 6.3 资料集中管理

- NAS 上的资料文件夹可配置为知识库**监视文件夹**：文件新增、修改、删除会被自动感知并重新学习，无需人工导入；
- 对话中可直接附加 NAS 上的文件与文件夹（含 SMB / UNC 网络路径）；
- 知识库内容在对话时带出处引用，可追溯至原始文件。

> **注意**：挂载卷的根目录（如 `/volume1` 本身）不接受递归扫描，必须指定其下的子文件夹（如 `/volume1/立案资料/`）。这是防止全盘扫描导致进程卡死的保护机制，不影响正常使用。

### 6.4 定时总结报告

配置定时数字人，按设定周期自动执行：

1. 汇总知识库期内新增与变更的资料；
2. 汇总对话与任务记录中的关键信息；
3. 生成 Word / PDF 总结报告，落入 NAS 指定目录；
4. 可按需推送至邮箱或企业微信。

触发周期、汇总范围、报告模板均在实施阶段与客户确认后配置。

### 6.5 前提条件

| 项 | 要求 |
|---|---|
| NAS 架构 | **x86_64**，支持 Docker（群晖 Container Manager / 威联通 Container Station 等） |
| 内存 | 建议 8 GB 以上 |
| 存储 | 资料所在存储池可读写，并可为容器挂载 |
| 网络 | 构建镜像时需联网拉取基础镜像与依赖；运行时可离线 |
| AI 网关 | 容器运行环境可访问模型接口 |
| 端口 | 容器端口可在内网访问（默认 8080） |

| 限制 | 说明 |

| Linux 构建不含 AI 终端 | 服务端形态不提供 AI 终端能力，其余功能完整 |
| ARM 架构 NAS 不支持 | 仅支持 x86_64，ARM 型号群晖等无法运行 |
| 单一邮箱身份 | 邮件统一从配置账号发出，与桌面端规则一致 |
